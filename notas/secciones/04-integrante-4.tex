\textbf{Proyecto:} CLAB, gestión de laboratorios y reservas. El esqueleto tiene dos servicios de consulta, sin reservas persistidas ni replicadas \cite{clabEsqueleto2026}.

\subsection*{Modelo supuesto y demostración sencilla}
\texttt{send()} bloquea al hilo. \texttt{sendAsync()} devuelve un futuro; el \texttt{join()} final sí espera \cite{java17httpclient}. Los límites son 2 s para conectar y 3 s para la petición. Un timeout no prueba cancelación del servidor. Es distinto de conexión rechazada o HTTP 503.

Las diapositivas muestran un modelo supuesto: el cliente pide un dato a A y A consulta a B. La demo sencilla utiliza dos procesos locales, con respuesta normal y retardo de 5 s en el puerto 8083. Se compara la espera del cliente y el agotamiento del plazo. Las salidas individuales no son una comparación de rendimiento. La relación con el PFC se explica oralmente.

\subsection*{Aplicación oral al PFC y decisiones}
Para relacionar el modelo con CLAB, A sería Reservas (8082) y B sería Laboratorios (8081). Reservas recibe \path{/api/reservas/comunicacion} y consulta \path{/api/laboratorios/info}, con HTTP/JSON y \texttt{RestClient} bloqueante. Ese flujo ya se probó en una máquina. La API oculta las clases internas, pero las direcciones y los fallos siguen visibles.

\textbf{Propuesta, no implementada:} futuras réplicas aisladas no confirmarían horarios sin acuerdo con la autoridad de escritura. Se priorizaría consistencia de confirmación sobre disponibilidad durante una partición. Con red sana, mantener datos consistentes cuesta coordinación y latencia. Detener un proceso no prueba esas garantías ni una partición \cite{ahmed2023consistency}.

\subsection*{Fallo, comparación y conclusión}
Detenido Laboratorios, la excepción interna produjo HTTP 503 en 178 ms. Reservas atendía, pero su consulta quedó indisponible. Tras el reinicio manual, otra petición obtuvo 200 en 312 ms. No hubo failover ni reintentos automáticos.

MRBS ya reserva y previene conflictos \cite{mrbs2026}; este esqueleto solo consulta. Separarlo permitió reiniciar Laboratorios independientemente, a cambio de una dependencia de red. Para futuras escrituras, limitaría reintentos e identificaría la operación para evitar duplicados ante resultados inciertos \cite{azureRetry2026}.
